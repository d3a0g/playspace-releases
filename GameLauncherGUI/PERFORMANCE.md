# Профили графики

Профиль сохраняется для каждой игры. По умолчанию автоприменение выключено, в том числе у старых профилей. Кнопка «Применить и играть» сохраняет профиль с включённым автоприменением и передаёт выбранную игру общему механизму запуска. Обычная кнопка запуска тоже применяет включённый профиль.

Поддержка зависит от адаптера:

- Unity: разрешение и режим экрана через штатные параметры Player. Универсальных команд для FPS, качества и масштаба нет; эти переключатели недоступны.
- CS2: разрешение, оконный/полноэкранный режим и `+fps_max`.
- MECCHA CHAMELEON и Palworld: разрешение и режим запуска Unreal. Для качества, масштаба рендера, VSync и лимита FPS нужен существующий `GameUserSettings.ini`. Файл определяется в стандартных каталогах текущего пользователя или выбирается явно. Без конфигурации безрамочный режим не предлагается.
- Остальные игры без адаптера: сохранение плана без автоматического применения.

При редактировании Unreal-конфига обновляются только известные ключи секции `GameUserSettings` и `ScalabilityGroups`. Остальные секции, комментарии и настройки сохраняются. Перед первым изменением создаётся `GameUserSettings.ini.playspace-backup`; повторное применение её не заменяет. «Восстановить» возвращает исходные байты и отключает автоприменение профиля.

Параметры производительности объединяются с путями UE4SS, а не заменяют их. Для Steam используется `steam.exe -applaunch` с отдельными аргументами. Часть игр может переопределять настройки движка: работоспособность в каждой версии игры требует отдельного игрового теста. Настройки драйверов NVIDIA/AMD, разгон, системные службы и процессы других приложений не меняются. Целевой FPS — цель или лимит, а не прогноз производительности.

Проверки конфигураций, восстановления, аргументов и интерфейса используют только временные файлы и не запускают игры:

```powershell
dotnet run --project GameLauncherGUI.Tests/GameLauncherGUI.Tests.csproj -c Release -- --ui
```
