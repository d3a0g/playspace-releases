# Публикация обновлений PLAYSPACE

Лаунчер читает маленький JSON-файл по постоянной HTTPS-ссылке при запуске и каждый час, в том числе в трее. Если версия новее текущей, показывает окно и отправляет уведомление Windows через NotifyIcon. В трее окно не перехватывает фокус: нажатие на уведомление открывает предложение обновиться. Автоматическое уведомление одной версии отправляется один раз; ручная проверка доступна всегда. Настройки Windows, «Не беспокоить» и корпоративные политики могут подавлять системные уведомления.

Обновление открывается в браузере по кнопке. Лаунчер не скачивает и не запускает EXE автоматически. После скачивания закройте PLAYSPACE через «Выход» и распакуйте новый выпуск. Библиотека, аккаунт Steam и пользовательские настройки хранятся отдельно в LocalAppData/GameLauncherPRO и сохраняются при замене файлов приложения.

## Где хранить

Проще всего: отдельный публичный репозиторий только с готовыми выпусками или HTTPS-хостинг файлов. Исходный код может находиться в закрытом репозитории. Клиентам нужен доступ к latest.json без авторизации. Не встраивайте токен доступа к приватному репозиторию в приложение.

Google Drive тоже подходит: загрузите архив и latest.json, для обоих включите чтение «Все, у кого есть ссылка». Адрес канала должен указывать на сам JSON, а не на папку. Лаунчер преобразует ссылку https://drive.google.com/file/d/FILE_ID/view в запрос скачивания этого файла. В дальнейшем заменяйте содержимое того же файла latest.json, сохраняя FILE_ID и доступ. Ограничения загрузок и страницы подтверждения Google Drive могут мешать проверке; для большого числа клиентов лучше обычный HTTPS-хостинг.

Закрытый репозиторий/Drive без открытой ссылки требует собственного серверного посредника или отдельной системы входа пользователей. Текущий клиент не содержит общих секретов для доступа. Ссылка downloadUrl может вести на приватную страницу релиза, но для скачивания пользователю потребуется доступ и вход в браузере.

## Формат latest.json

```json
{
  "version": "1.1.0",
  "downloadUrl": "https://YOUR-HOST.example/releases/PLAYSPACE-1.1.0-win-x64.zip",
  "notes": "Исправления и новые возможности.\nПодробности новой версии."
}
```

Номер состоит из 2–4 числовых частей, для выпусков используйте три: 1.0.0, 1.1.0, 1.1.1. Сравнение числовое: 1.10.0 новее 1.9.0. Текущая версия задаётся Version в csproj или параметром публикации. Предварительные версии вида 1.1.0-beta не поддерживаются.

## Первая публикация

1. Создайте постоянный файл latest.json на выбранном хостинге и получите его HTTPS-ссылку.
2. Укажите этот адрес в GameLauncherGUI/update-source.json, поле feedUrl. Этот файл копируется рядом с EXE и входит в публикацию. В исходниках уже указан действующий канал; при пустом адресе сетевых проверок не будет.
3. Подготовьте выпуск командой из корня репозитория:

   ```powershell
   ./tools/Publish-Release.ps1 -Version 1.0.0 -FeedUrl 'https://YOUR-HOST.example/latest.json'
   ```

4. Загрузите полученный ZIP, затем укажите его HTTPS-ссылку в latest.json с той же версией. Распространяйте весь архив, включая update-source.json.
5. Для следующего выпуска увеличьте номер, например до 1.1.0, загрузите новый архив и последним обновите содержимое latest.json. Уже установленные приложения сравнят версию и предложат загрузку.

Если адрес архива известен заранее, скрипт также создаст latest.json:

```powershell
./tools/Publish-Release.ps1 -Version 1.1.0 -FeedUrl 'https://YOUR-HOST.example/latest.json' -DownloadUrl 'https://YOUR-HOST.example/releases/PLAYSPACE-1.1.0-win-x64.zip' -Notes 'Описание изменений'
```

Скрипт ничего не публикует в интернет и не перезаписывает существующие папки выпусков. Домен YOUR-HOST.example — заполнитель, его необходимо заменить своим адресом.

## Настройки пользователя

«Настройки → Приложение»: флажок уведомлений, версия, адрес канала, сохранение канала и ручная проверка. После изменения адреса нажмите «Сохранить канал», затем «Проверить обновления». Адрес из настроек имеет приоритет над update-source.json. Пустое поле возвращает встроенный адрес.

Пункт «Уведомления об обновлениях» в меню трея переключает тот же параметр. Выключение подавляет автоматическое окно и системное уведомление; фоновые проверки и ручная проверка работают. Настройка сохраняется после перезапуска. Изменение поведения крестика не сбрасывает её.

## Проверки

`dotnet run --project GameLauncherGUI.Tests/GameLauncherGUI.Tests.csproj -c Release -- --ui`

Проверяется сравнение версий, разбор JSON, HTTPS-ссылки, ограничение размера, ответы сервера, сохранение уведомлений, меню трея и окно обновления. Реальный хостинг должен быть настроен отдельно.

Документация NotifyIcon: https://learn.microsoft.com/dotnet/api/system.windows.forms.notifyicon.showballoontip
## Действующий канал

- Репозиторий сборок: https://github.com/d3a0g/playspace-releases
- Последний выпуск: https://github.com/d3a0g/playspace-releases/releases/latest
- Постоянный JSON: https://github.com/d3a0g/playspace-releases/releases/latest/download/latest.json
- Первый настроенный выпуск: 1.0.1. Исходники и пользовательские данные не опубликованы.

Выпуск 1.0.1 нужно один раз установить/распространить целиком. Старые сборки с пустым каналом сами не узнают адрес — его можно указать вручную в настройках. Последующие новые версии обнаруживаются автоматически; установка скачанной сборки по-прежнему выполняется вручную.

Следующий выпуск можно собрать и сразу опубликовать одной командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Publish-ToGitHub.ps1 -Version 1.0.2 -Notes 'Описание изменений'
```

Для публикации используется сохранённая авторизация GitHub CLI. Файлы сначала загружаются в черновик, затем выпуск публикуется как latest. Персональные данные и токены в ZIP не включаются. Номер существующего выпуска повторно использовать нельзя.


## Переименование, выпуск 1.0.2

Новый EXE: LauncherPlaySpace.exe. Новый формат архива: LauncherPlaySpace-<версия>-win-x64.zip. Имя сборки и сведения о продукте изменены, namespace исходного проекта и папка пользовательских данных сохранены для совместимости. Канал обновлений не изменился. Прежний GameLauncherGUI.exe из старой папки больше не запускайте после перехода на новый выпуск.

В репозитории опубликовано расширенное описание из distribution/README.md. Репозиторий оставлен публичным по выбору автора; ограничение «только по ссылке» на GitHub не применяется.
