# История Git и дальнейшая работа

Первый крупный импорт исходников `e07bb6195ce3455fa700bd551356f396fb7cb457` добавил 11 313 строк и удалил 26. Это снимок уже написанного проекта, а не последовательная история его разработки. Такой коммит затрудняет проверку отдельных изменений. Подтверждения того, что он получен squash или amend, нет.

При проверке основного репозитория теги указывали на разные коммиты: `v1.0.4` — `ce161d259ac2886939f774c83f8be019d85ae082`, `v1.0.5` — `864b224e53606b538a9822115ff2500ab23b5f74`. Две версии за день допустимы; качество изменений этим не подтверждается. Повторный коммит `61eb2f9` с названием изменения README не изменил дерево файлов: это лишняя попытка публикации. Публичная история сохранена без переписывания.

Для дальнейшей разработки:

1. Работать в обычном локальном Git checkout и отдельной ветке задачи.
2. Проверять `git diff` и добавлять только относящиеся к задаче файлы.
3. Разделять исправления, перемещения файлов и изменения поведения на самостоятельные коммиты.
4. Собирать проект и запускать подходящие проверки до Pull Request.
5. Публиковать проверенный коммит через Git, затем привязывать тег и сборку к конкретному SHA.
6. Не переписывать уже опубликованную историю ради видимости более аккуратной разработки.

Старый API-скрипт `tools/Publish-Source.ps1` накладывает снимок файлов поверх удалённого дерева. Его нельзя использовать для публикации этой реорганизации: он оставит старые пути. Для неё нужен обычный Git push подготовленных коммитов после отдельного разрешения на публикацию.

## Проверки безопасности

Срабатывания антивирусов требуют расследования. Ни история Git, ни отсутствие отдельных детектов не доказывают безопасность программы. Отчёты установщика и основного EXE нужно различать и сопоставлять с SHA-256 конкретных файлов. Новая локальная сборка не наследует результаты проверки старой сборки. Сохранённые отчёты и ограничения опубликованы в [разделе безопасности](../security/README.md).
