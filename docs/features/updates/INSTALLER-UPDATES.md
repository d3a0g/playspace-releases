# Обновление через установщик

Новые выпуски публикуют `LauncherPlaySpace-<версия>-Setup.exe`. Поля `downloadUrl` и `installerUrl` в `latest.json` указывают на установщик. Поэтому установщик получают и старые версии лаунчера, читающие только `downloadUrl`.

Окно обновления предлагает «Обновить и перезапустить». Браузер не открывается: установщик загружается внутри приложения с прогрессом, объёмом и средней скоростью. Перед запуском проверяются SHA-256 из `installerSha256` и заголовок EXE. Отмена и ошибка удаляют недокачанный файл. Для старого канала без установщика или контрольной суммы показывается объяснение; неподтверждённый пакет не запускается.

После загрузки копия лаунчера в отдельной временной папке запускает интерфейс обновления. Основное окно закрывается только после подтверждения готовности копии. Она ждёт завершения основного процесса, повторно проверяет пакет и запускает Inno Setup с `/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART /NOCLOSEAPPLICATIONS /NORESTARTAPPLICATIONS` и явным каталогом текущего EXE. Установщик передаёт реальный процент через `CurInstallProgressChanged` и файл, указанный в `/PLAYSPACEPROGRESS`. Пока процент недоступен, отображается неопределённый прогресс; замена файлов не отменяется из интерфейса.

После успешного кода завершения и проверки установленной версии запускается новый EXE. Временные файлы удаляются при запуске новой версии; при ошибке установки остаётся журнал `install.log`, путь показывается в интерфейсе. Мастер установки скрыт, но системные предупреждения Windows/SmartScreen не обходятся. Обычная установка для текущего пользователя не требует повышения прав; запись в защищённый каталог может завершиться ошибкой.

Установщик использует прежний идентификатор приложения и каталог предыдущей установки, предлагает закрыть работающий лаунчер и устанавливает файлы поверх него. Настройки и библиотека в каталоге данных сохраняются. Для переносной копии без зарегистрированной установки создаётся обычная установка; после этого используйте её ярлык.

ZIP остаётся дополнительным файлом релиза для переносного использования. Встроенная установка требует EXE и `installerSha256`; адрес установщика не угадывается. При обновлении переносной копии выбран её текущий каталог, при этом установщик регистрирует приложение в Windows.

Изменения заработают в новых клиентских сборках и при публикации канала с контрольной суммой. Старый уже выпущенный клиент сам по себе не получит новый интерфейс до обновления.

`tools/Publish-Release.ps1` собирает приложение, ZIP и установщик Inno Setup. Требуется `.tools/InnoSetup/ISCC.exe` либо параметр `-Compiler`. `tools/Publish-ToGitHub.ps1` загружает оба пакета и их SHA-256, а канал обновлений направляет на EXE. Изменение этих скриптов само по себе ничего не публикует и не меняет уже выпущенный канал.
