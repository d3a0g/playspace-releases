# Windows блокирует закреплённый ярлык

На скриншоте указан `LauncherPlaySpace.lnk` из `User Pinned\TaskBar`. Если распакованный `LauncherPlaySpace.exe` запускается напрямую, это отличается от блокировки самого EXE. Происхождение файла и применённую политику нужно проверять на том ПК, где возникает ошибка.

## Что сделать на затронутом ПК сейчас

1. Открепите неработающий значок PlaySpace от панели задач.
2. Переместите распакованный EXE в постоянную папку, если он всё ещё находится во временном каталоге или внутри открытого ZIP.
3. Запустите сам `LauncherPlaySpace.exe` из этой папки.
4. Щёлкните правой кнопкой по значку **запущенного** лаунчера на панели задач и выберите «Закрепить на панели задач».

При необходимости создайте новый обычный ярлык локально через Проводник: правая кнопка по EXE → «Показать дополнительные параметры» → «Отправить → Рабочий стол (создать ярлык)». Не переносите старый скачанный `.lnk` между компьютерами.

В версии 1.0.4 добавлены кнопки **«Настройки → Приложение → Ярлык на рабочем столе / Ярлык в меню „Пуск“»**. Они создают новый стандартный ярлык на текущий `LauncherPlaySpace.exe`, с абсолютным путём, пустыми аргументами и рабочей папкой рядом с EXE. Существующий ярлык не перезаписывается. Автоматического закрепления на панели задач нет — это действие пользователя через оболочку Windows.

Настройки Smart App Control, Defender, AppLocker и WDAC не меняются. Метки интернет-происхождения не удаляются ни с EXE, ни со старых ярлыков. Новый ярлык не обходит проверку самого приложения и не гарантирует разрешение любой корпоративной политики.

Если блокируется также EXE или новый локальный ярлык, требуется диагностика политики на затронутом ПК. Для распространения приложения с подтверждённым издателем нужна действительная подпись доверенным сертификатом; самоподписанный сертификат не равно доверие Windows. В текущем проекте сертификат издателя отсутствует, автоматическая подпись или отключение защиты не добавлялись.
